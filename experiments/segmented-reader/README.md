# Segmented native resource-text reader v0.2.7

Target: Minecraft 1.21.1 / NeoForge 21.1.265 / official MTR 4.1.0-beta.2. This separate candidate adds two classes to v0.2.6; every existing v0.2.6 class entry remains byte-identical.

A later 4 GiB full-pack v0.2.6 run exhausted the heap while native IOUtils repeatedly grew a complete model-text StringBuilder. This candidate redirects only IOUtils.toString inside the exact released ResourceManagerHelper UTF-8 string-reading lambda. The same InputStreamReader decoder fills bounded character segments, and public String.join builds the final String once. It preserves UTF-16 code units across segment boundaries. Resource lookup, priority, debug reading, outer stream closure and native error handling remain intact; no model, texture or interaction behavior changes.

The audit compares against the unique active commons-io 2.15.1 JAR, covering all 8,534 asset JSON/Blockbench/OBJ/MTL inputs in the official release and selected 16 archives. It passes 51 synthetic comparisons including multiple charsets, malformed sequences, split supplementary characters, BOM, NUL and short reads. Ownership and propagated I/O failure checks pass.

Isolated allocation counters across three warmed reads measure 127,270,416 native bytes versus 53,278,992 candidate bytes for 8,800,000 ASCII code units (58.1% lower); 129,588,240 versus 72,326,808 for 4,800,000 Unicode code units (44.2% lower). These controls establish allocation reduction in the reader, not full-client peak memory or 4 GiB reliability. [Audit](reader-audit.json).

The first native 4 GiB run passed full-pack startup and foreground F3+T reload, each with 2,541 registrations, 651 completed unique source parses and 60 seconds of stable fresh observations. No OOM or model-load failure occurred. Both DC01 bodies and open doors render before/after; both distinct floor/doorway caches match v0.2.6 exactly. Read-only jstat sampled startup/reload heap peaks of 3.734/3.777 GiB; Windows working-set samples peaked at 5.369/5.592 GiB. These are sampled observations, not true maxima. Passenger v0.1.1 stayed fixed. Original player and saved transport fields, all 16 pack hashes/selections and installed mod identities were verified after normal shutdown. See [startup](../../evidence/neoforge-v027-4gb-startup.json), [reload](../../evidence/neoforge-v027-4gb-reload.json) and [fixture verification](../../evidence/neoforge-v027-4gb-fixture-verified.json).

A second fresh process also passed full-pack 4 GiB startup and actual F3+T reload, each with all 2,541 vehicles / 290 objects / 23 rails, 651 completed sources and a 60-second stable check. Its sampled startup/reload heap peaks are 3.768/3.871 GiB, working sets 5.596/5.581 GiB. Both DC01 cars render before/after with unchanged native interaction caches. Both clients closed normally and original fixture/player/pack/mod verification passed. The exact audited v0.2.7 artifact is now [delivered](../../dist/releases/mtr-memory-sharing-neoforge-v027.jar); [acceptance and fingerprints](../../evidence/neoforge-v027-4gb-acceptance.json).

Two successful processes establish repeatability for this fixture, not arbitrary worlds or a lower process peak than v0.2.6's historical successful run. The initial before-reload camera missed a train at platform B; retained that image and captured actual rendering separately. Passenger v0.1.1 stayed fixed during both tests and remains experimental.
