## Summary

**`0.4.8`** is a scoped client-side development pre-release for **Minecraft `1.21.1`**, **Java `21`**, **NeoForge `21.1.265` (exact)**, and **Official MTR `4.1.0-beta.2`**.

This release resolves the multi-reload heap exhaustion observed on earlier builds (`0.4.7` 4th-reload BBModel `String.join` OOM and initial `0.4.8` 7th-reload OBJ `String.join` OOM) by streaming Blockbench, OBJ, and MTL inputs through single owned `DELETE_ON_CLOSE` UTF-16 snapshots and computing SHA-256 digests in a single read/write pass.

---

## Key Changes in `0.4.8`

- **Streaming Blockbench, OBJ & Material Inputs**: Replaces synchronous whole-`String` assembly (`String.join`) on audited `ResourceProvider` paths with owned UTF-16 file snapshots and bounded `8 KiB` readers/streams (`StreamedObjCache`, `ResourceTextSnapshot`), preserving native parsing and mesh construction.
- **Single-Pass Snapshot Digest (`engineering-055`)**: Computes UTF-8 SHA-256 inside the `FilterReader` pipeline while writing the UTF-16 snapshot channel, eliminating the redundant full-channel disk read pass before parsing. Across six balanced `AB/BA` pairs on the real `65.26 MB` `02a05_arknight.bbmodel` input, median thread CPU time dropped by **19.24%** (wall-clock elapsed **−19.37%**, 6/6 pairs improved).
- **Retained Core Memory Architecture (`0.4.x` / `0.3.x` Foundation)**: Keeps lossless 36-byte `Deflater.BEST_SPEED` packed vertices (`0` CPU `StoredVertexData`), `PartType.DISPLAY`-only transform retention, epoch-shared vehicle JSON trees, `96 MiB` bounded text LRU, `2 + 64` bounded descriptor scheduling, and `MixinInitialisationError` startup rejection (exit code `1`) on mismatched MTR JARs.

## Validation Scope vs Known Limits

### Verified on exact `official-nf265` product JAR (`920c1f83...`)

- **Automated Suites**: `106` Java unit/regression tests (including `-Xmx64M` 40 MiB BBModel/OBJ streaming vs `String.join` OOM controls), `682` historical script index checks, and `354` Python tool tests pass.
- **Packaged Client & Binary Mismatch Checks**: Passes `69` actual packaged client checks (`24` lifecycle + `18` strict-resource + `27` OBJ), full sixteen-pack startup (`1,092` declarations / `1,091` distinct IDs), readable JFR summary, and fatal exit code `1` before registration when launched against an altered MTR JAR ([nf265-packaged](https://github.com/teamCreating/MTR-Memory-Saver/tree/main/evidence/engineering-056/nf265-packaged)).
- **20 Consecutive Full 16-Pack `F3+T` Reloads (`3 GiB` Heap)**: Passes `20 / 20` consecutive native `F3+T` reloads in a fresh `-Xms512M -Xmx3072M` G1 JVM (`epochs 3–22`, `19` intermediate dual-clock `>= 60 s` stable intervals, `14/14` post-20 samples over `65.003 s`, zero OOM, clean `Alt+F4` exit `0`, readable `213.90 MB` JFR), independently replayable via `evidence/engineering-056/nf265-reload20/verify_sealed.py` ([nf265-reload20](https://github.com/teamCreating/MTR-Memory-Saver/tree/main/evidence/engineering-056/nf265-reload20)).

### Not Yet Certified / Excluded Scope

- **Whole-Client Performance Unconfirmed**: Earlier `12-JVM` paired Spark trials on `NF248` (`943b3d45...` vs `v0.3.0`) missed the performance gates (`−0.282%` steady private memory vs `<= -10%`; `+9.840%` loading time vs `<= +5%`), with concurrent host workloads leaving timing attribution `inconclusive` ([practical-spark](https://github.com/teamCreating/MTR-Memory-Saver/tree/main/evidence/engineering-054/practical-spark), [outlier-sensitivity](https://github.com/teamCreating/MTR-Memory-Saver/tree/main/evidence/engineering-054/outlier-sensitivity)). The optimized `920c1f83...` candidate has not yet completed a full 48-JVM controlled client benchmark.
- **Open Functional Gates**: Independent display-frame timing (ETW permission error / empty PresentMon CSV), a 2-hour uninterrupted route, and exhaustive full-catalog vehicle visual/window/door/boarding checks remain pending.
- **Custom `Performance v6` Excluded**: Only `official-nf265` is built and released for `0.4.8`; `v6` work remains paused.

## 简体中文说明

**`0.4.8`** 是面向 **Minecraft `1.21.1` 客户端**、**Java `21`**、**NeoForge `21.1.265`（精确版本）** 与 **官方 MTR `4.1.0-beta.2`** 的限定范围开发预发布版本。

本版本针对前期构建在连续重载时触发的堆耗尽问题（`0.4.7` 第 4 次重载 BBModel `String.join` OOM 与 `0.4.8` 初版第 7 次重载 OBJ `String.join` OOM），改用单一所有权的 `DELETE_ON_CLOSE` UTF-16 快照流式读取 `.bbmodel`、`.obj` 与 `.mtl`，并将 SHA-256 哈希计算合并进写盘读取的单遍循环中。

### 主要更新

- **BBModel / OBJ / MTL 全链路流式读取**：在已审计的原生 `ResourceProvider` 入口以流式快照代替 `String.join` 整块字符串拼接（`StreamedObjCache`、`ResourceTextSnapshot`），保留原生解析与网格计算逻辑。
- **单遍边写边算哈希优化（`engineering-055`）**：在 `FilterReader` 写入 UTF-16 通道的同一遍循环内计算 UTF-8 SHA-256，省去解析前的二次读盘步骤。以 `65.26 MB` 真实 `02a05_arknight.bbmodel` 运行 6 对均衡 `AB/BA` 微基准测得：NF265 线程 CPU 中位下降 **19.24%**，墙钟耗时下降 **19.37%**（6 对全部改善）。
- **既有基础机制**：保持 36 字节/顶点 `Deflater.BEST_SPEED` 无损压缩（`0` 个 CPU `StoredVertexData`）、仅留 `PartType.DISPLAY` 变换、同世代共享车辆配置 Gson 树、`96 MiB` 有界压缩文本 LRU、`2 + 64` 有界调度队列以及不匹配 MTR JAR 注册前退出码 `1` 拦截（`MixinInitialisationError`）。

### 验证范围与未关闭限制

- **已验证项（产物 JAR `920c1f83...`）**：
  - `106` 项 Java 回归测试（含 `-Xmx64M` 流式 vs `String.join` OOM 负对照）、`682` 份历史脚本校验与 `354` 项 Python 工具测试全部通过；
  - 实机 `NF265` 客户端通过 **69 项**打包检查（24 生命周期 + 18 严格资源 + 27 OBJ）、全 16 包启动（`1,092` 声明 / `1,091` 去重 ID）、JFR 读取及假包注册前退出码 `1` 拒绝；
  - 在 `-Xms512M -Xmx3072M`（`3 GiB` 堆上限）下连续通过 **`20 / 20`** 次真实全 16 包 `F3+T` 热重载（`epochs 3–22`，`19` 个中间 `>= 60 s` 双时钟稳定区间，末轮后 `14/14` 样本覆盖 `65.003 s`，`0` OOM，`Alt+F4` 正常退出码 `0`，可读 `213.90 MB` JFR）。
- **未认证 / 待关闭项**：
  - **尚不能宣称整客户端性能达标**：此前在 `NF248` 上运行的 12-JVM 实用 Spark 对照（`943b3d45...` vs `v0.3.0`）未达到 `-10%` 稳态私有内存与 `+5%` 加载门槛（实测 `−0.282%` / `+9.840%`），且因并发宿主机负载导致耗时因果归因 `inconclusive`；优化后的 `920c1f83...` 尚未运行 48-JVM 整客户端对照协议。
  - **其余 P1 待闭门禁**：独立显示帧呈现采集（ETW 权限拒绝 / PresentMon 无有效 CSV）、两小时连续路线（历史 01–03 失败）及全车系外观/车门/上下车交互。
  - **定制 `Performance v6` 除外**：`0.4.8` 仅发布 `official-nf265`，`v6` 目标继续暂停。
