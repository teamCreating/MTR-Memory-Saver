# Continuous native reload-before recorder

Engineering evidence, 2026-11-16 (UTC+08:00). This tool records evidence for an existing JVM. It never launches a client, sends game input or changes a world.

`tools/reload_before_recorder.py record --instance <prepared-instance> --output <new-directory> --expected-count <distinct-ids> --expected-declarations <declarations>` verifies the actual Windows process executable, arguments and creation time through an owned process handle and freezes the launch plan, receipt, metadata and reader sources. It samples once per second by default. Create `<output>/stop-request` to stop only the collector; `--duration-seconds` is available for a bounded engineering test.

Every capture preserves its source bytes, including duplicate snapshot reads. Raw blobs are shared only when their complete bytes agree; each capture independently retains its raw references. Successful canonical before records require the unchanged 15-second freshness rule, actual unpaused in-world null-screen state, pinned neutral 1.0.2 target/process/catalogue, zero native pending/in-flight/observation errors, stable native epoch/diagnostic streams, and the existing exact-default diagnostic attribution. A resource transition or non-game state is recorded as ineligible. Genuine read, source-integrity, process or publication failures are retained and stop the collector.

The before payload contains distinct capture-start and capture-completion timestamps. Its exclusive writer flushes, calls `fsync`, closes, and only then obtains the actual payload-close time for `receipt.json`. The receipt is also flushed/synced/closed; only afterwards does the SHA-chained journal append a published event with the actual receipt-close time and receipt SHA. No completion time is predicted or backdated. Selection chooses the uniquely nearest receipt closed before the actual input, checks the entire chain and raw hashes, and requires both native observation and publication to lie within 15 seconds. A later failed/ineligible observation invalidates the older candidate.

After actual CUA input, save the unaltered factual receipt fields (`method="native_f3_t"`, `provider`, boolean `succeeded`, `issued_at`, `confirmed_at`) and run `tools/reload_before_recorder.py confirm --output <recorder-directory> --receipt <receipt.json>`. Confirmation first preserves the original receipt and submission. A valid before record is passed through the existing `observe_packaged_client.confirm_reload_input` API. Stale, failed or missing selections become rejected input events; an input whose provider reported failure keeps `succeeded=false`. No reload is counted by this tool.

Full-chain consumers must call `reload_before_recorder.input_events(output)`. It cross-checks `inputs.jsonl` against every immutable `input-attempts/` submission/result, so interrupted confirmations, lock conflicts, duplicate ledger records and omitted attempts fail explicitly. Reading only the JSONL stream is insufficient. The existing module-oriented `full_reload_evidence` has not been changed by this recorder; neutral final reload validation requires the separate adapter.

The 26 recorder tests cover actual-contract replay, immutable write-close timing, reader ownership, stable source streams, error preservation, truncated logs, exited JVMs, unique-before selection, 15-second expiry, hash changes, failed input receipts, repeated use and missing attempts. Four existing Windows snapshot tests exercise real `ReplaceFileW`/shared-reader behavior and preserve actual filesystem errors. Raw test logs and source snapshots accompany this evidence.
